# PRD — AI VOC Decision Lab

## 1. 문제

제품팀은 앱 리뷰, 고객센터, 인터뷰, 설문에 흩어진 VOC를 매주 수작업으로 읽고 정리한다. 요약 결과가 원문과 연결되지 않으면 우선순위 토론에서 신뢰를 얻지 못하고, 같은 검증을 여러 직군이 반복한다.

## 2. 목표 사용자와 JTBD

- 주요 사용자: 3~20명 규모 제품팀의 PM/PO, UX 리서처, CX 매니저
- 보조 사용자: AI 엔지니어, 데이터 분석가, QA
- JTBD: “다음 스프린트의 문제를 정할 때, 고객 근거와 품질 수준을 함께 확인해 빠르게 합의하고 싶다.”

## 3. 가설

1. 인사이트마다 원문 ID를 제공하면 검수 시간이 30% 이상 줄어든다.
2. 기회 점수의 구성 요소를 공개하면 우선순위 합의 시간이 20% 줄어든다.
3. 골든셋 평가를 릴리스 전에 실행하면 프롬프트 회귀를 배포 전에 발견할 수 있다.

## 4. 핵심 흐름

1. 사용자가 기간과 데이터셋을 선택한다.
2. 시스템이 개인정보·중복·형식 오류를 검사한다.
3. VOC를 주제로 묶고 도달률·심각도·신뢰도로 기회 점수를 계산한다.
4. 사용자는 문제 카드를 선택해 인용된 원문을 검수한다.
5. 검수된 문제에서 PRD 초안과 수용 기준을 만든다.
6. 골든셋 평가를 실행하고 GO·ITERATE·ROLLBACK을 결정한다.

## 5. 기능 요구사항

| ID | 요구사항 | 수용 기준 |
|---|---|---|
| FR-01 | VOC 분류 | 분류 결과에 theme, confidence, evidenceIds가 포함된다. |
| FR-02 | 근거 확인 | evidenceIds는 입력 데이터에 실제 존재하는 ID만 허용한다. |
| FR-03 | 우선순위 | 점수 구성 요소와 계산 방식이 UI와 문서에 공개된다. |
| FR-04 | PRD | 문제, 사용자 스토리, 해결 가설, 수용 기준, 성공 지표, non-goal을 포함한다. |
| FR-05 | 평가 | 주제 정확도, 인용 유효성, 안전 통과율을 골든셋으로 계산한다. |
| FR-06 | 실패 복구 | LLM 오류·8초 타임아웃·스키마 오류 시 로컬 베이스라인으로 되돌아간다. |

## 6. 비기능 요구사항

- 샘플 데모는 외부 API와 네트워크 없이 완전히 동작한다.
- 500건을 초과하는 단일 요청은 거부한다.
- 원문 내부 지시는 데이터로 취급하고 시스템 지시로 실행하지 않는다.
- API 키는 클라이언트 번들에 포함하지 않는다.
- 키보드, 모바일, reduced-motion 환경을 지원한다.

## 7. 지표와 이벤트

- North Star: 검수 완료된 문제 신호 수 / 주
- 품질: 주제 정확도, 인용 유효성, 안전 통과율, 사람 검토율
- 제품: 첫 인사이트 도달 시간, 인용 클릭률, PRD 채택률, 재분석률
- 운영: p95 지연시간, 요청당 비용, fallback 비율, 오류율

주요 이벤트: `dataset_selected`, `analysis_run`, `theme_opened`, `evidence_opened`, `prd_generated`, `eval_run`, `release_decision_recorded`.

## 8. 출시 계획

- Alpha: 내부 3개 제품팀, 합성+비식별 데이터, 모든 결과 수동 검수
- Beta: 5% 사용자, 품질 기준 통과 시에만 노출, fallback 관측
- GA: 최소 2주간 인용 유효성 100%와 안전 통과율 95% 이상 유지 시 확대

## 9. 범위 제외

- 자체 파운데이션 모델 학습
- 고객사별 장기 데이터 저장과 SSO
- 모든 협업 도구의 양방향 동기화
- 자동으로 백로그를 확정하거나 티켓을 생성하는 기능
