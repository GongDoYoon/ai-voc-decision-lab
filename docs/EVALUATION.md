# Evaluation design

## 목표

“좋아 보이는 답변”이 아니라 제품 결정에 안전하게 사용할 수 있는지를 검증한다. 평가는 모델 선택, 프롬프트 수정, 분류 규칙 변경 때마다 동일하게 재실행한다.

## 평가 집합

`data/golden-set.ts`에 대표 VOC 8건을 관리한다.

- 핵심 문제 4종: 안정성, 신뢰, 온보딩, 협업
- 운영 실패: 동기화 실패, 근거 없는 생성
- 안전: 프롬프트 인젝션과 타 사용자 데이터 요청
- 모호성: 한 주제로 확정하기 어려운 짧은 불만

## 지표

| 지표 | 정의 | 가중치 | 게이트 |
|---|---|---:|---:|
| Theme accuracy | 기대 주제와 예측 주제 일치율 | 65% | ≥ 85% |
| Citation validity | 입력에 존재하는 ID만 인용한 비율 | 20% | = 100% |
| Safety pass rate | 안전 시나리오 정책 통과율 | 15% | ≥ 95% |

종합 점수는 가중 평균이며 85 이상을 GO 후보로 본다. 단, 인용 유효성이 100% 미만이면 종합 점수와 무관하게 출시하지 않는다.

## 실패 모드와 대응

| 실패 모드 | 탐지 | 대응 |
|---|---|---|
| 존재하지 않는 VOC 인용 | allowed ID 검증 | 결과 폐기 후 로컬 fallback |
| JSON 스키마 불일치 | 런타임 shape 검증 | fallback 및 오류 기록 |
| 프롬프트 인젝션 | 안전 골든셋 | 입력을 untrusted data로 격리 |
| 모호한 문제 신호 | 낮은 confidence | REVIEW 큐로 전달 |
| API 지연·장애 | 8초 timeout | 로컬 베이스라인 반환 |

## 알려진 한계

현재 8건은 회귀 테스트를 설명하기 위한 작은 골든셋이다. 운영 전에는 실제 비식별 VOC를 층화 추출하고, 두 명 이상의 라벨러 합의와 세그먼트별 오류 분석을 추가해야 한다.
