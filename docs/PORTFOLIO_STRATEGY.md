# AI 기획·개발 지원 관점 포트폴리오 전략

## 현재 GitHub에서 보이는 강점

- Java/JSP/Spring Boot 기반 웹 서비스의 기본 구조를 경험했다.
- 게시판, 심리상담, 픽업·배송 등 서로 다른 도메인의 서비스 아이디어를 코드로 옮긴 흔적이 있다.
- Pull Shark 등 협업 이력이 있고, 기술 스택의 폭이 넓다.

## 채용 관점에서 부족하게 보이는 신호

1. 공개 저장소가 모두 2022년에 멈춰 있어 최근 실행력이 보이지 않는다.
2. 대표 README가 한두 줄이라 문제 정의, 본인 역할, 의사결정, 결과를 검증할 수 없다.
3. `.svn`, `build/classes` 등 생성 산출물이 포함돼 저장소 위생과 협업 습관이 약해 보인다.
4. AI 기획에 필요한 PRD, 성공 지표, 실험, 품질 기준, 실패 대응이 없다.
5. AI 개발에 필요한 Python/LLM/RAG·Agent, structured output, 평가, 관측, API·배포 경험이 보이지 않는다.

## 이 프로젝트가 메우는 공백

| 필요한 신호 | 프로젝트 증거 |
|---|---|
| 사용자 문제 구조화 | PRD, JTBD, 가설, 범위와 non-goal |
| 기술 이해와 프로토타이핑 | TypeScript 엔진, API route, optional LLM adapter |
| 신뢰 가능한 AI | 근거 ID 검증, fallback, prompt injection 방어 |
| 평가 역량 | 골든셋, 가중 지표, 회귀 테스트, 출시 게이트 |
| 제품 판단 | 기회 점수, 성공 지표, 제한 배포·롤백 조건 |
| 협업 가능성 | 문서화, 테스트, 명확한 저장소 구조 |

## 다음 추천 프로젝트

1. **도메인 RAG**: 본인이 잘 아는 산업 문서 50~100개로 검색 품질을 평가하고 chunking·reranking 실험을 비교한다.
2. **도구 사용 Agent**: 캘린더·메일 대신 안전한 샌드박스 도구를 호출하고, task success와 tool-call accuracy를 측정한다.
3. **실사용 개선 사례**: 5명 이상에게 사용하게 하고 행동 지표·인터뷰를 바탕으로 v2를 만든다.

지원할 때는 저장소 링크만 붙이지 말고 “어떤 실패를 발견했고, 어떤 기준으로 출시하지 않았는지”를 두 문장으로 설명하는 것이 좋다.
